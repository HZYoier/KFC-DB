# 成员 C 第三阶段报告

> 成员 C：黄柏源；学号：24325108。

成员 C 负责库存、补货、库存审计、权限和第三阶段集成。

## 业务实现

- `sp_adjust_inventory` 检查员工身份、调整数量和库存下限，成功时写入库存、库存流水及业务审计。页面调用 `fn_replenishment_qty` 取得数据库给出的补货建议量。
- `tr_Inventory_Audit` 按受影响的库存行记录现有量、锁定量、操作人和时间。店长可在库存页打开只读审计列表，按原料 ID 查看最近 100 条匹配记录。
- 25c 验证部分收货、收齐、重复收货拒绝和第二次收货失败后全量回滚，提交 18/0、回滚 14/0。

## 版本和权限

正式迁移在同一事务依次安装三域对象、装载权限、检查对象并写入 v1.1 标记。实际交付增加六个权限码。店长获得报表执行、销售视图和两个表值函数查询、审计只读及补货函数执行。值班经理可执行补货函数。目录、业务角色映射、数据库授权分别核对。13c 使用版本标记选择预期值，第二阶段回归两版各 38/0，第三阶段合并验收 123/0。

## 并发

正式 v1.1 上，订单提交后收货将 P 从 8 增至 13，订单回滚后收货将 P 从 10 增至 15。两端反向操作时，死锁图定位到库存和库存流水的键锁，收货事务作为 1205 牺牲者完整回滚。按原料 ID 升序逐项取得更新锁后，同一业务对照仅产生普通等待，订单和采购单均提交。各场景三轮，每轮三会话事务计数均为零。
