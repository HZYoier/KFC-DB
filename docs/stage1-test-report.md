# 第一阶段完整测试报告

## 1. 测试目标

验证 `main` 能从空数据库一次完成关系模型、约束、业务过程、查询视图、种子数据和最小权限部署，并覆盖计划中的 E2E-01 至 E2E-07。验收以仓库唯一入口 `sql/run_all.sql` 为准，不依赖手工切换数据库或窗口变量。

## 2. 测试环境

| 项目 | 值 |
| --- | --- |
| 日期 | 2026-10-01 |
| 实例 | `localhost\MSSQLSERVER2` |
| SQL Server | 17.0.1000.7 RTM，Developer Edition（64-bit） |
| 数据库 | `KFC_DB`，兼容级别 170 |
| 身份验证 | Windows 身份验证 |
| 客户端 | `sqlcmd` / ODBC Driver 18 |

执行命令：

```powershell
sqlcmd -S "localhost\MSSQLSERVER2" -E -N o -C -f 65001 -b -i "sql/run_all.sql"
```

执行前确认测试实例中的 `KFC_DB` 已删除，从而验证真正的空库部署路径。`-b` 使任一 SQL 错误返回非零退出码，`-f 65001` 保证中文脚本按 UTF-8 读取。

## 3. 测试思路

1. **空库黑盒部署**：只调用唯一入口，验证脚本顺序和跨域依赖。
2. **域内断言**：A、B、C 分别验证成功路径、边界条件和事务回滚。
3. **跨域闭环**：验证定价快照、订单状态、库存锁定/释放/实扣、积分两段式、补货审批和分批收货。
4. **权限正反测试**：既验证岗位允许的操作，也验证越权读取、过程调用、敏感字段直接更新和骑手跨单操作被拒。
5. **白盒清点**：部署后核对表、主外键、CHECK、过程、视图、角色和精确授权数量。
6. **接口契约检查**：独立执行只读检查器，核对 A/C 提供给 B 的对象、参数顺序、类型、精度和可选参数默认值。

## 4. 执行过程

`run_all.sql` 按以下顺序执行：建库 → A/B/C 建表 → A/C/B 过程与约束 → 三域视图与查询 → 角色权限 → A/C/B/C 种子 → A/B/C 验收。

审计期间补齐了两类缺口：

- B 的 `09b_order_seed_data.sql` 在异常事务被 `XACT_ABORT` 标记为不可提交时，改为先 `ROLLBACK` 再 `REVERT`，避免 Msg 3930 覆盖原始错误。
- C 的 E2E-07 增加收银员直接更新商品价格、库存、顾客积分均返回 229，以及骑手确认他人配送单返回 52702 的断言。
