# I-B08 决策材料：同商品多行与顶层输入规则

> B；2026-10-14；状态：待C需求核对、A/C消费者审查及全组2.2冻结。本文不改变SQL或唯一开放问题表状态。
> 关联：[B问题清单](b-issues.md) I-B08、[教学映射](source-requirements.md) R5-13。

## 1. 已确认事实

- SalesOrderItem 主码order_item_id；无(order_id,product_id)唯一约束。一个商品跨不同套餐父项出现多行是合法结构。
- sp_create_order 的 @items 按product_id查重复，52108拒绝重复顶层商品；52110拒绝同请求套餐父商品及其配置子商品均作为顶层输入。
- @parents保存order_item_id/product_id/quantity；组件用每条父项的真实order_item_id关联，数量乘本父项数量。
- R5-13提示“不要默认同一商品在一张订单只能出现一次”，不等同于已经要求某个特定JSON协议；需C解释并形成可追溯决议。
- 现有业务不存定制备注，不为证明重复行价值而虚构规格、定制或行级优惠功能。

## 2. 两个可执行选择

| 项目 | 方案A：保留顶层商品唯一输入 | 方案B：允许重复售卖行及套餐子商品另购 |
| --- | --- | --- |
| 请求 | 同product_id数量在客户端合并；K与其子商品同单另购仍按当前规则拒绝 | 每个输入对象成为一条独立SELLABLE，K展开自己的COMPONENT；另购单品是独立SELLABLE |
| 现有错误 | 保留52108/52110 | 停用这两项拒绝语义，保留非法数字/商品/组件保护；错误码去留由C登记 |
| 明细键 | 现有代理键不变，结构仍允许多行 | 同样保留代理键，不加商品组合唯一键 |
| 成交价 | 每商品一次定价快照 | 同时刻同商品逐行调用同源A函数，当前规则应相同；不提前新增行折扣 |
| 组件映射 | 当前每父行展开 | 必须始终依order_item_id展开，禁止以product_id回连父项造成乘方扩增 |
| 库存 | 单品与组件按原料SUM | 重复行和单独另购的需求均计入SUM；套餐父项不再按BOM重复计 |
| 教学解释 | 必须证明“表不限制多行、顶层聚合只是当前接口规则”满足R5-13；无法说明则不能选 | 直接支持同商品多行，但仍要说明为什么不需要复合唯一 |
| 成本 | 实现零改动，输入限制需清晰告知 | 需改B输入验收/父项展开校验、A/C集成样例、界面行模型与回归；不用先改表 |

方案A的客户端合并只适用于相同product_id的普通顶层重复输入；不能把套餐组件抬成售卖行，也不能通过“数量合并”突破现有K与其子商品的同单限制。

## 3. 方案B的实施要点（若获批）

1. 输入仍仅允许product_id/quantity，不接收price/item_role/parent；禁止客户端注入组件和非法数量的守卫不变。
2. 保留重复输入行，不按product_id去重；@parents必须保留每个独立order_item_id，确认OUTPUT父行数量等于输入对象数。当前父子展开以父行ID为锚，逐段核对，不能仅删两条IF就宣称完成。
3. 每个套餐输入父行独立展开，即便同一个套餐出现两次也不得跨父项归并。单品另购有自己的SELLABLE行，不与套餐COMPONENT合并。
4. 总额只SUM SELLABLE；组件零价。C需求按全部合法制作项汇总：单品SELLABLE+COMPONENT；不重复展开套餐父项或忽略另购商品。
5. 输入JSON顺序不是当前承诺的持久化行序；若界面需要稳定行号应在契约中另定，不能假定IDENTITY顺序就是原数组顺序。
6. 旧的合法无重复请求仍可用；更新BT-11、B12套餐回归相关覆盖，确认A/C定价/BOM/库存视图不因多行JOIN放大。
7. 只在11b实施批准改动，05原始文件保持v0.1；联动A契约、C授权/回归材料，但B不直接编辑其实现。

## 4. 决议用例

| 输入（符号为真实商品ID） | 方案A预期 | 方案B预期 |
| --- | --- | --- |
| P1数量1、P1数量2 | 52108；无副作用 | 两SELLABLE，数量1/2，总额=3×P1价 |
| K数量1、K数量2 | 52108 | 两套餐父项，分别展开各自数量；总需求等于K×3 |
| K数量1、P1数量1（P1为K组件） | 52110 | 一套餐父项、一另购单品；组件与另购都计需求 |
| 两不同套餐共享P1 | 当前可接受，两个父项各有组件 | 保持可接受，不合并父键 |
| 重复商品加非法客户端price | 52106优先于重复守卫 | 仍52106；支持重复不降低输入保护 |

每个成功用例还须验证价格快照、原料锁/实扣、支付/退款总额、积分与厨房展示；期望以A夹具当前有效价与C BOM计算，不硬编码现有种子ID。
