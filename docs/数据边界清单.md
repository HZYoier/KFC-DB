# 二、数据边界清单

需要追溯、统计、审计的都进数据库

库存相关统一术语：**账面量（现有量）**＝物理在库数，库存表实字段；**锁定量**＝被订单占用数，库存表实字段；**可售量＝现有量−锁定量**

## 2.1 必须入库（核心业务事实）

### 商品与配方域

| 数据 | 进/不进 | 理由 |
| --- | --- | --- |
| 商品基础信息（名称、分类、标准基价、状态） | 进 | 主数据，价格引擎与点单的前提 |
| 商品分类 | 进 | 多对多归属、按类统计 |
| 套餐与子商品分组关系（含各子项数量） | 进 | 套餐拆分、出餐、成本核算都依赖它 |
| 物料清单 BOM（商品×原料×用量） | 进 | 锁库存、扣库存、算成本的源头 |
| 原料主数据（单位、安全库存线） | 进 | 补货决策的基准 |

### 促销与定价域

| 数据 | 进/不进 | 理由 |
| --- | --- | --- |
| 促销活动表（类型、起止时段、状态） | 进 | 价格引擎的规则来源 |
| 促销商品规则表（周×时段、一口价9.9、适用范围） | 进 | 促销规则可配置、可追溯 |
| 套餐自身独立优惠 | 进 | 作为规则的一部分 |

### 顾客/会员域

| 数据 | 进/不进 | 理由 |
| --- | --- | --- |
| 顾客主表（类型：散客/WOW/付费） | 进 | 订单需要顾客信息 |
| 会员等级、积分倍率、等级门槛 | 进 | 决定积分与升级 |

### 订单/支付/积分域

| 数据 | 进/不进 | 理由 |
| --- | --- | --- |
| 订单主表（下单时间、顾客、总额、状态、取餐方式/码、各环节时间戳） | 进 | 业务核心 |
| 订单明细（商品、数量、成交价快照、命中促销ID、套餐拆分子项） | 进 | 历史价格不受日后改价/改活动影响 |
| 支付记录（方式、实际金额、时间、第三方流水号） | 进 | 对账需要 |
| 积分流水（待生效→已生效，关联订单） | 进 | 防重复到账，这是"预计算再落账"两段式的关键 |
| 配送记录（骑手ID、取餐/送达时间、状态） | 进 | 配送留痕，取/送时间可追溯 |

### 库存与补货域

| 数据 | 进/不进 | 理由 |
| --- | --- | --- |
| 库存表（账面/现有量 + 锁定量） | 进 | 锁定时只加锁定量、不动账面——防超卖的核心字段 |
| 库存变动流水（锁定/扣减/入库，时间+单据号） | 进 | 审计可回溯，第3阶段做补货预测没有流水寸步难行 |
| 补货建议单（原料、当前库存、建议量、状态） | 进 | 用于补货预测 |
| 采购/调拨单、入库收货记录（回写库存、关单） | 进 | 单据信息留档、库存闭环 |

账号权限域：员工账号、业务角色、角色-权限映射、操作审计日志 → 进

## 2.2 不进库（应用层 / 内存 / 外部）

| 数据 | 进/不进 | 理由 |
| --- | --- | --- |
| 购物车中间态 | 不进（纯会话/缓存） | 高并发临时状态，落库价值低；仅在结算那刻生成订单。若需跨设备保存会员购物车，再单独加一张（灰色地带） |
| 后厨 KVS 队列 | 不进 | 完全由订单状态（待制作/制作中）实时派生，另存队列会双写不一致 |
| 制作工艺步骤/参数（火候、油温、时长） | 不进 | SOP 文档范畴，属文件；数据库只存用料（BOM），不存"怎么做" |
| 叫号广播 / 取餐屏实时推送 | 不进 | 设备间实时短消息；取餐码本身在订单表里 |
| 骑手实时 GPS 轨迹 | 不进 | 第三方运力平台数据；只留取/送两个时间点 |
| 第三方支付完整报文、卡号、密钥 | 不进 | 安全合规；只取业务所需字段+流水号，凭证走支付平台 |
| 会员密码/认证令牌明文 | 不进 | 只存哈希或交认证服务 |
| 小票打印格式、UI、通知文案 | 不进 | 展示层，与业务数据无关 |

## 2.3 灰色地带（给出建议取向）

| 数据 | 建议 | 说明 |
| --- | --- | --- |
| 散客是否建档 | 建议按手机号轻量建档 | 不然订单没 customer_id，第4阶段按顾客维度分析无从谈起；可选"游客临时ID"过渡 |
| 每日销售/经营汇总 | 第3-4阶段再建分析表/物化视图 | OLTP 不预存派生聚合，避免手工维护对不上 |

## 设计要点提示（跨清单呼应）

两个可提醒的设计点：

1. **"成交价快照 + 命中促销ID"入明细** —— 这条边界决定了促销改规则不动历史账，务必落库而不是用视图现算。
2. **两段式积分（待生效→生效）+ 订单终态触发** —— 依赖状态机，所以订单主表必须留终态时间戳，这也是第4阶段按日/月统计销量的前提。
