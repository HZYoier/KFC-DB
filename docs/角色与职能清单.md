# 一、角色与职能清单


## 1.1 后台管理侧

| 角色 | 核心职责（对应流程） | 触碰的数据/状态迁移 | 权限边界（建议） |
| --- | --- | --- | --- |
| 店长 | 录入/维护商品基础信息（名称、分类、标准基价）；为商品绑定物料清单 BOM；配置促销活动（如疯狂星期四：周× 时段 + 一口价9.9）；审核补货建议单并审批为采购/调拨单；分配员工账号与权限 | 商品、分类、BOM、促销活动表/促销商品规则、补货单(审批态)、采购单、员工账号 | 主数据写权限；补货单仅审核/驳回；看全部营业报表 |
| 值班经理 | 日常运营看板：查看库存预警；确认或手动调整补货建议单数量后提交审批；外送高峰调度/叫第三方骑手；处理卡单/丢单/退款等异常 | 库存(读)、补货建议单(创建/调整)、配送状态(读)、订单异常处理 | 只读库存，能建/调补货建议单但不能审批；异常订单处置需店长授权 |

## 1.2 门店作业侧

| 角色 | 核心职责（对应流程） | 触碰的数据/状态迁移 | 权限边界（建议） |
| --- | --- | --- | --- |
| 收银员 / POS操作员 | 扫商品入车 → 调用价格引擎计价 → 确认下单（生成订单主表+明细快照）；收款（现金/扫码），支付成功将订单 待支付→已支付 | 订单(创建)、支付记录(写)、购物车(内存态) | 只能创建与收款；不能改价、不能改已生成订单 |
| 厨师（后厨） | 看厨房队列 KVS（已支付待制作）；点开始制作：订单→制作中，记录开始时间 | 订单状态(制作中) | 仅能看“已支付/制作中”订单与定制备注，看不到价格/会员信息 |
| 配餐员 | 核对定制备注（去酱/加辣）；点制作完成——触发库存扣减（锁定转实扣）；堂食打包叫号 / 外送放保温架；顾客取餐 → 已取餐 | 订单状态、库存扣减(触发器/存储过程执行)、取餐码 | 只读订单；出餐状态迁移；不触碰金额 |
| 服务员 | 堂食递餐具、引导、协助叫号 | 基本无库写 | 最小权限，只读桌台/取餐信息 |
| 骑手（第三方） | 到店扫码取餐 → 配送中；送达确认 → 已完成；记录骑手ID与取送时间 | 配送记录(写：骑手ID/取餐/送达时间)、订单终态 | 最小权限：只能读写分配给自己的配送单 |

## 1.3 顾客侧

| 角色 | 说明 | 权限边界 |
| --- | --- | --- |
| 散客 | 临时客；建议按手机号轻量建档（否则订单缺顾客标识，无法跨单分析） | 只能查/改自己的订单与档案 |
| WOW会员（免费） | 基础积分倍率、会员价资格 | 同上 |
| 付费会员（如大神卡/宅神卡） | 更高积分倍率、专属价；等级达标自动升级 | 同上 |

顾客身份区分 + 等级倍率 → 直接影响积分预计算，所以会员表要存：类型、等级、当前总积分、等级门槛（门槛可放配置表，后续阶段调整方便）。

## 1.4 系统自动行为（权限主体：DB内部逻辑 / 应用后端）

| 行为 | 触发的数据操作 | 说明 |
| --- | --- | --- |
| 价格引擎 | 实时匹配当前时间 vs 促销时段 → 得出成交价+命中促销ID | 结果快照入订单明细，防止日后改规则影响历史 |
| 防超卖锁库 | 下单即按 BOM 锁定原料：锁定量↑、可售量↓ | 由存储过程/事务保证原子性 |
| 积分预计算 | 支付成功 → 生成待生效积分流水 | 不累加总积分；防重复到账 |
| 积分到账+升级 | 订单进终态 → 流水转已生效、累加、判断是否达升级门槛 | 终态驱动 |
| 库存比对+补货建议 | 扣库存后扫现有量 vs 安全库存线，低于则自动生成建议单(待审核) | 触发器中判断或后台作业 |
