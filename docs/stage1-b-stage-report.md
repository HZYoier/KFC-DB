# 成员 B 第一阶段报告：订单、支付与履约

> 成员 B：24325328 张奕希

## 1. 阶段目标

成员 B 负责把“顾客下单 → 库存锁定 → 支付 → 制作 → 自取或配送 → 积分到账 / 取消退款”转化为可执行、可回滚、可追溯的关系数据库实现，并与 A 的定价/积分接口、C 的库存/审计接口联调。

## 2. 实验思路

本实验采用“关系模型约束 + 存储过程状态机 + 跨域事务 + 正反验收”的方法：

1. 用外键、唯一键和 CHECK 约束保证订单、支付、配送与积分流水的静态合法性。
2. 所有业务写入通过 8 个存储过程完成，不向岗位角色开放表级写权限。
3. 下单时调用 A 的统一定价函数保存成交快照，并在同一事务中调用 C 的锁库过程。
4. 支付、制作完成、取餐/送达和退款分别作为状态机迁移点；任一跨域调用失败，订单与库存/积分一起回滚。
5. 用种子订单跑通三类真实路径，再用回滚型验收脚本构造非法输入、事务故障和越权反例。
6. 最终不单跑 B 文件，而是从空库执行 A/B/C 完整链，证明接口和脚本顺序可以共同工作。

## 3. B 域交付物

### 3.1 关系表

- `SalesOrder`：订单主表和全流程时间戳。
- `SalesOrderItem`：单品/套餐父项/套餐子项与成交价快照。
- `Payment`：支付、退款金额和第三方交易号。
- `Delivery`：骑手、取餐、送达状态和时间。
- `PointLedger`：支付金额、积分倍率和积分变动快照。

### 3.2 业务过程

`sp_create_order`、`sp_pay_order`、`sp_start_production`、`sp_finish_production`、`sp_pick_up_order`、`sp_pick_up_delivery`、`sp_confirm_delivery`、`sp_cancel_or_refund_order`。

### 3.3 查询与视图

四个视图：`v_order_detail`、`v_kitchen_queue`、`v_customer_point_ledger`、`v_pickup_board`。

三条具名查询：待制作订单、某订单完整履约记录、某顾客积分流水。

## 5. 实验过程

### 5.1 空库部署

删除本机项目测试库后，仅执行：

```powershell
sqlcmd -S "localhost\MSSQLSERVER2" -E -N o -C -f 65001 -b -i "sql/run_all.sql"
```

入口依次建立三域表、约束、过程、视图、角色、种子和验收对象。B 的三笔种子订单分别为：

- `B-SEED-PICKUP-001`：周四促销、自取完成、LOCK → CONSUME、积分生效。
- `B-SEED-DELIVERY-001`：外送完成、配送时间完整、LOCK → CONSUME、积分生效。
- `B-SEED-CANCEL-001`：未支付取消、LOCK → RELEASE、无有效积分。

### 5.2 事务与错误路径

重点验证：非法 JSON、数量为零、停用商品、无 BOM、未支付开工、金额不匹配、重复支付、无有效会员等级、积分流水外键故障、非法状态跃迁、价格改动不影响历史快照、套餐展开、取餐/送达积分生效和全额退款。

审计还复现了 `XACT_ABORT ON` 下不可提交事务中先 `REVERT` 会报 Msg 3930 的问题。`09b` 已统一为“先回滚事务，再恢复模拟身份，再重抛原错”，保证失败路径不会掩盖根因。

### 5.3 权限与跨域联调

- A 接口：`fn_get_effective_product_price`、`sp_apply_customer_points`。
- C 接口：锁库、释放、实扣、分批收货和审计过程。
- 收银员只能调用下单/支付过程，不能直接更新商品价格、库存或顾客积分。
- 骑手只能确认分配给自己的配送单。
- 接口检查器验证对象、参数顺序、数据类型、精度以及 `@received_qty = NULL` 的兼容默认值。
