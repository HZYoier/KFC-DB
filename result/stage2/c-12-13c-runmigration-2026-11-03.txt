## Phase 1 — first-round differences and attribution

1. **12 without 11b correctly refused.**
   `12: required v1.0 procedures are missing ...` (53404). This is the intended
   gate, not a defect: the six B queries are part of the 57-code whitelist and
   must exist before grants can be verified.

2. **13c alias compile error (4104).**
   Four `SchemaVersion` selects used `sv.batch_id` without an `AS sv` alias.
   Attribution: C's new 13c draft; fixed by adding the alias in all four batches.

3. **13c EXCEPT collation conflict (468).**
   `sys.database_principals.name` (Latin1_General_CI_AS_KS_WS) vs the expected
   table (Chinese_PRC_CI_AS) in the 70-pair grant comparison. Fixed with
   `COLLATE DATABASE_DEFAULT` on the three actual-side expressions in both
   `EXCEPT` directions.

4. **13c EXEC expression syntax error (102).**
   `@ordered_at = SYSDATETIME()` was written directly in an `EXEC` argument;
   SQL Server rejects expressions in that position. Fixed by assigning
   `@ctx_now DATETIME2(0) = SYSDATETIME()` first.

5. **13c cust_app 229 fixture reported 3930.**
   The expected permission failures were caught inside an explicit transaction;
   `SET XACT_ABORT ON` made the transaction uncommittable, and the subsequent
   `REVERT` raised 3930. Actual errors were 229/229. Fixed by following H16:
   `ROLLBACK` first, `REVERT` second, then assert. This is a fixture correction,
   not a permission leak.

6. **run_migration without 11b.**
   `:r sql/stage2/11b_order_migration.sql` returned "文件名无效" and sqlcmd
   exited; the open transaction rolled back 11a/11c/12. Verified after exit:
   `RolePermission=52`, no `Permission`, no `UQ_Category_category_name`,
   only `v0.1` in `SchemaVersion`. This is the intended safe failure.
